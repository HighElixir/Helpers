# StateMachine 改善点

## 1. 命名の一貫性不足
- `Thead` / `Threading`、`Extention` / `Extension`、`LogLevelExtention` / `LogLevelExtension` が混在。
- 学習コストと保守コストを上げている。

## 2. 例外・キャンセル方針の統一不足
- エラーハンドリングが箇所依存で、運用ルールが読み取りづらい。
- 非同期処理で `CancellationToken` の扱い基準が明文化不足。

## 3. 性能評価の基準不足
- 遷移数増加時や `LazySend` 多用時の定量基準が薄い。
- GC 監視指標（alloc/frame）の運用が弱い。

## 4. 学習導線の重さ
- 機能が豊富で、初期導入時に必要な最小セットが埋もれやすい。
- 標準運用（QueueMode、ログ、Dispose）を迷いやすい。

## 5. テスト網の不足
- コアテストはあるが、互換移行や性能回帰の継続監視は強化余地あり。
